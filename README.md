# Schulweg (prototype)

Retro top-down browser game prototype: a kid walks, rides and sneaks to school through a small town.
Phaser 3.90.0 (from jsDelivr, includes Matter.js), native ES modules, no build step.

**Status: the full prototype (stories 1.1 to 1.11) is built.** Not yet verified: the 60 FPS target on a real phone (only desktop CPU cost was measured, see [docs/PERFORMANCE.md](docs/PERFORMANCE.md) for numbers and the manual phone test).

## Run (Windows PowerShell)

The game must be served over HTTP; `file://` breaks ES modules.

```powershell
cd C:\docs\projekte\grand-theft-study
npx serve .
# or
python -m http.server 8080
```

Open the printed URL (`http://localhost:3000` or `http://localhost:8080`). URL flags: `?debug` (FPS, physics outlines, pool counters, bully paths), `?q=low|medium|high` (quality for this load), `?bench` (stepping benchmark and smoke test, see below). For a phone on the same network see the protocol in docs/PERFORMANCE.md.

## Features

- Walk (sprint with stamina), ride a bike (slides, skid marks, bell), surfaces that change speed and grip (asphalt, cobble, grass, puddles).
- A 96x64 tile town with two routes from home to the school, an objective arrow with distance, zoom that follows speed.
- Living world: wind, rain with puddles (T), particles, pushable props, flags.
- Chase: the skatepark and the back of the schoolyard are bully turf; bullies see, chase, search and give up (levels 0 to 2, A* pathfinding). Hide in hedges, dumpsters and phone booths to escape; if you are caught a comic frame shows, you lose a euro and respawn at home.
- Slingshot with wind-bent aim; pebbles only affect objects (cans, crates, trash cans), never people or animals. Hits lure bullies.
- Throwing stick (Q / E): a long, wind-bent boomerang throw that topples balls, frisbees and kites stuck in trees, makes far-away bullies look, flies past people and animals, lands as a pickup you walk over to collect, and that a chasing dog fetches back.
- Stick (Q / E, third tool, "Stock"): a close-range swing that smashes crates and cardboard boxes, flings cones, shakes bushes for daily loot, rings doorbells (Ding-Dong, then a harmless ding-dong-run), bursts the party pinata, and the slingshot pops the kirmes balloons. It only ever affects objects, never people or animals.
- Menu and pause overlay with language (Deutsch / English) and quality (Low / Medium / High); touch controls, gamepad and keyboard.

## Controls

Every player has an intent snapshot, `ctx.input.intents[i]`; all devices produce the same one (`ctx.input.intent` aliases `intents[0]`); `ctx.input.type` is `keyboard`, `touch` or `gamepad` (whichever was used last) so prompts can adapt.

| Action | Keyboard / mouse | Touch | Gamepad |
| --- | --- | --- | --- |
| Walk | WASD / arrows | joystick (left half) | left stick or d-pad |
| Jump (rings the bell on the bike, ollie on the skateboard, hop on skates; also lets go of a bus with an ollie) | Space | big button | A |
| Manual (hold to balance, skateboard only) | C or Left Ctrl | small board button (only shown on a skateboard) | LT |
| Sprint | Shift | double-chevron button | B |
| Interact (mount / dismount bike, skateboard or skates; hold it behind a bus on skates to hang on) | F | circle button | Y |
| Tool use / aim (hold to charge, release to fire; with the stick: one swing per press, held = a swing every 0.35 s) | left click, aim at the cursor | tool button (tap swings), drag from it to aim | RT, right stick aims |
| Next / previous tool | E / Q | small triangle button | RB / LB |
| Block (hold) / dodge roll (press while walking) | R | shield button | X |
| Kiai (shout that makes bullies stumble) | V | burst button | right-stick click |
| Map | M | - | Back |
| Weather (clear / rain) | T | - | - |
| Pause | Esc | pause button (top right) | Start |

**Two players** (AD-18; the number of active players is `ctx.players.length`; the game starts with one, or with two in co-op, see below; `SCHULWEG_GAME.addPlayer()` with `?debug` adds a second to a running one-player game). Bindings live in `data/input.json` (KeyboardEvent codes); with a single player the arrow keys and Right Shift also steer P1, so one-player controls are unchanged.

| Action | P1 | P2 |
| --- | --- | --- |
| Walk | WASD | arrow keys |
| Jump / bell / ollie | Space | Right Ctrl |
| Manual (skateboard) | C or Left Ctrl | `/` |
| Sprint | Left Shift | Right Shift |
| Interact | F | Enter |
| Previous / next tool | Q / E | `,` / `.` |
| Block / dodge | R | `;` |
| Kiai | V | `'` |
| Tool use / aim | left click at the cursor | Numpad0, aims the way P2 last moved (or with a gamepad right stick) |
| Map, weather, pause | M, T, Esc / Start | - (global intents come from P1 only) |
| Minigame answer 1-4 (also `intent.answer`) | `1`-`4` (top row) | `Numpad1`-`Numpad4` |

Gamepads bind to the next free player: with one player the first pad is P1; with two players the first pad drives P2 and the second drives P1. Touch controls always drive P1.

### Co-op (local, two players on one screen)

**Menu flow** (`ui/menuFlow.js`, Phaser-free): Play, slot, New game, then the mode screen "Allein / Solo" or "Zu zweit / Co-op" (with the control hint: P1 WASD + Space, P2 arrow keys or gamepad), then the character select for P1 and, in co-op, a second one for P2 (the same kid twice is fine). In co-op P1 steers the select with A/D + Space (or mouse/touch) and P2 with the arrow keys + Enter or its gamepad; alone, every key and any pad works. The picks are stored through the actions `coop.set` and `player.setCharacter` per player and saved at once, so Continue restores the mode and both characters; the pause menu shows them ("Zu zweit: Lena + Jonas"). On a touch-only device (finger primary, no gamepad) co-op is not offered and the mode screen says why.

**Gamepads**: a pad connected on the mode screen shows "press A to join", and A picks co-op. In game the pads follow `data/input.json`: with two players the first pad drives P2, a second pad drives P1. If a pad that drives a player disconnects, a toast ("Controller getrennt" / "Controller disconnected", `ui:toast` event, `ui/hud/ToastModule.js`) shows for three seconds; the player stays in the game and steers with its keyboard bindings (P2: arrow keys). Joining a running one-player game with a pad is not offered (with one player the pad drives P1); start a co-op game instead.

**Start vehicles**: every player starts on its character's `startVehicle` (Lena the bike); Mehmet the skateboard, Jonas the skates (`characters/Characters.js`; an id without a profile or outside `playerVehicles` in `data/characters.json` means walking). There are no start items yet.

The `coop` flag in `state.shared.flags` (action `coop.set { on }`) decides at game start: on, `GameScene` creates two players from `state.players[0..1]`, each with its own character look, attributes, tool belt and start vehicle, bound to `intents[0]` / `intents[1]`, standing 24 px apart at the spawn (`data/camera.json` `coop.spawnOffsets`). Switching it on creates player 2 as another character than P1. The menu sets it (see below); with `?debug`, `SCHULWEG_GAME.setCoop(true)` also restarts the run with two players (`setCoop(false)` back to one). `GameScene` also accepts a start config `{ players: [{ character, vehicle }] }` for tests.

- **Camera** (`camera/CameraRig.js`, maths in `camera/rigMath.js`): follows the midpoint (a pinned player, see below, counts 60 %) and zooms out to keep both players 48 / 40 UI px inside the view. The existing speed zoom still applies; the smaller of speed zoom and fit zoom wins, and the same critically damped spring and sub-pixel handling smooth it. One player: identical to before.
- **Tether** (`camera/tetherMath.js`, `data/camera.json` `tether`): max distance 480 world px (vertical counts times the 16:9 aspect), well inside the view at the smallest zoom (0.6). From half of it the player walking away is slowed smoothly down to a stop at the limit, the one walking towards the other gets up to 12 % extra speed, and past the limit a gentle pull (capped) brings both back. A player held by a caught frame or screen (`player.pinned`) never blocks the other: the free one keeps at least 25 % speed and is pulled gently. `ctx.coop` is `{ active, distance, tetherRatio }`.
- **HUD**: P1's status (stamina, ground, vehicle) and tool/ammo at the left, P2's mirrored at the right (below the shared Ärger meter), money, clock and Ärger once, no touch layout for P2. One shared objective arrow orbits the camera centre. Each player has a coloured ring under the feet (P1 cyan, P2 orange; `?debug` adds a P1/P2 tag) and a small edge chevron appears when one is far from the screen centre.

Touch controls appear on touch devices and hide as soon as a key or mouse is used. In portrait on a touch device a rotate hint covers the game and input is ignored.
Resolution (AD-14): Medium and High render at 960x540, Low at 480x270. The picture is scaled by a whole number of device pixels (letterboxed, pixelated, so a 1920x1080 window shows 960x540 at 2x); only windows smaller than the render size get a fractional fit.
An FPS counter shows at the top left.

## Known limitations

- Placeholder procedural art, no audio, no saves (only language and quality are remembered), no school scene: arriving only shows a banner.
- Phone performance is unmeasured on real hardware (desktop proxy only); the reference phone is not chosen.
- Touch has no weather or map button; the map key does nothing yet.
- Bullies, props and the slingshot are tuned by feel, not playtested with children.
- Physics is fixed at 60 Hz steps; on screens above 60 Hz the picture is not interpolated.

## Movement and surfaces

Walking is the movement profile `foot` (`data/vehicles.json`). Hold Sprint to run faster; stamina (bar at the top left) drains while sprinting and refills when you stop. When it hits zero you move slower until it recovers to 25%. Stopping and turning slide a little, more on slippery ground. The label under the bar shows the ground you stand on; asphalt, cobblestone, grass and puddles change speed and grip (`data/surfaces.json`, which also defines unused snow and ice).
`node scripts/check-collisions.mjs` checks the collision category table.

## Bicycle

A bike is parked near the start. Walk up to it and press F to mount; press F again to get off (the bike stays where you left it). The `bike` profile in `data/vehicles.json` is much faster than walking on asphalt, slower on grass and cobblestones, has less grip, slides in hard turns and on puddles, and leaves fading skid marks and smoke when it skids or brakes hard. Space rings the bell (a ring appears and `bike:bell` is emitted on `ctx.events`). The camera zooms out smoothly with speed (1.0 standing to 0.6 at top speed, `data/camera.json`); the HUD shows the current vehicle. More bikes can be placed with `{ "type": "bike", "x", "y" }` objects in the map.

**Skateboard** (story 5.1, AD-23): a second profile on the same `MovementController` (no id branching): top speed 128 px/s on asphalt (bike 150, walking 70), snappy turning (`turnRate` 260), light drift, 1.1x on concrete, and a strong penalty on cobblestone (0.4, slower than walking, the rider sprite rattles with the surface's `rattle` value) and grass (0.35); puddles slow (0.5) and slide. All per-surface numbers are in `data/surfaces.json` (`speed.skateboard`). Boards lie around the town (`{ "type": "skateboard" }` map objects, `entities/Skateboards.js`): F next to one mounts it, F again gets off and the board stays on the ground (a bike standing closer wins the press, and one press only does one mount or dismount). Characters whose start vehicle is `skateboard` (Mehmet) start riding. Tricks, tuned in the profile's `trick` block and driven by the pure `vehicles/skateLogic.js`: **ollie** on the jump intent (Space): a short hop (lifted sprite over a ground shadow, crouch pose, longer when fast), during which the body ignores PROP bodies (cones, cans, crates, balls, bins; walls still stop it), landing dust through `ParticleHub.surfaceBurst`. **Manual** on holding the `manual` intent (C / Left Ctrl, P2 `/`, LT, touch button) at speed: a balance needle starts in the sweet window, rises while held and sinks when released; inside the window the board is balanced (1.1x speed through `MovementController.boostMult`), held too long it tips over and the rider simply drops back to rolling (short cooldown, no penalty); pulsing the button keeps it going. An ollie ends a manual. Events for the later trick system: `trick:ollie` and `trick:manual`, each `{ player, phase: 'start' | 'end', x, y, speed }` (ollie end adds `airtime`, manual end adds `time`, `sweet` seconds in the window and `reason` `over | under | slow | ollie`). The Mehmet perk `trickMultiplier` is used by the trick system below. Decision: skate clack is a small dust puff at the rear wheels (more often on rough ground); the `rattle` surface value had no consumer before, it now shakes the skateboard rider sprite.

**Tricks and Style** (story 5.2, AD-23, CAP-13): `vehicles/TrickSystem.js` is the per-player trick service (`ctx.tricks.forPlayer(i)`, also `player.tricks`; states `roll, ollie, grind, manual, stairs-jump, ramp`), its Phaser-free maths is `vehicles/trickCore.js`, all numbers are `data/tricks.json`. It scores what the board does and reads the `rail`, `bench`, `ramp` and `stairs` map objects (only it reads their grind data; art in `vehicles/trickArt.js`, drawn once per map). **Grind**: an airborne rider in the last part of a hop (`grind.descent`) that is over a rail (or a bench's steel edge) at a fitting angle (`grind.angle`, either direction) lands on it, slides along the polyline at the entry speed with sparks (ParticleHub `spark`), needs no balance and rolls off at the rail end or jumps off with an ollie (bonus points; the rail ignores the rider for `offCool` s). `rail` objects are `points` in continuous tile coordinates plus a `width` in tiles; a bench grinds along its centre line. **Stairs**: `dir` is the way down. Rolling down without an ollie rattles (the board slows, the sprite shakes, a comic "Rumpel-Rumpel!"), an ollie taken on the stairs at speed is a stairs jump worth points per step and lands safely. **Ramps**: rolling onto a `ramp` in its `dir` at speed launches a longer, higher hop (fake height like the ollie, `ramp.height`), scored by airtime. **Style**: every trick adds points (airtime, balanced manual seconds, steps, grind metres), tricks within `combo.window` s chain and grow a multiplier (x the character's `trickMultiplier` perk, so Mehmet grows faster); a trick unlike the last two scores a variety bonus, the same trick twice a repeat penalty. The chain is banked when the window runs out (it stands still while airborne, grinding or in a manual), when the player gets off the board or leaves the map. Banking pays `floor(points x centsPerPoint)` cents (`wallet.earn` reason `trick`) and XP (`xp.add`) through state actions and emits `style:banked` `{ player, points, multiplier, tricks, bailed, reason, cents, xp }` (the Tempo growth hook in `data/attr-growth.json` listens to it); a chain below `bank.minValue` just fades. A bail (hitting a wall, being caught, a manual falling over at a multiplier of 2 or more) banks `bailShare` (60%) of it, never less, a small chain loses nothing. Other events: `style:changed` `{ player, points, multiplier }`, `style:trick` `{ player, id, name, points }`, `trick:grind` / `trick:ramp` `{ player, phase, ... }`. From a multiplier of 4 a fire trail (ParticleHub `fire`, tier-scaled and pooled) follows the board. HUD: `ui/hud/StyleModule.js` (one per player, `data/hud.json`) shows points and multiplier, the window timer bar, the last three trick names and a "Eingelocht! +€ 0,74 · 29 XP" popup with a sparkle. Decisions: the combo shows its current value (points x multiplier) as `points`; getting off the board is the clean "bank action"; tricks exist on the skateboard and the skates. **Bank spots** (story 5.4): a `bank-spot` map object (`x`, `y`, `r` tiles) banks an active chain cleanly with a bonus when a rider rolls through its ring on the ground, not in a manual, at most `bankSpot.maxSpeed` px/s (`data/tricks.json`, `canBankAt` in `vehicles/trickCore.js`); `style:banked` then has `reason: 'bank-spot'`, `bonus` (a share) and `spot` (the object id) and the Style popup says "Sauber gebankt! ... +30%". A chain below `bank.minValue` is left to grow, a bail never gets the bonus.

**Skates and bus grab** (story 5.3, AD-23, CAP-14): the `skates` profile (Inliner) runs on the same `MovementController` (no id branching) and is the most agile ride: acceleration 270 and `turnRate` 340 (skateboard 150 / 260, bike 170 / 170), top speed 112 px/s on asphalt (1.12x on concrete, 0.95x on paths), but cobblestone (0.26) and grass (0.22) are crippling, with a strong rattle (`fx.rattleJitter`) and less grip: `data/surfaces.json` has `speed.skates` per surface and the new optional `gripMult` table (per profile grip factor on a surface, used for cobble, grass, puddle, snow and ice); puddles slow (0.45) and slide, ice (0.9 speed, grip 0.15 x 0.8) is defined for the winter. Lying skates are `{ "type": "skates" }` map objects (`entities/Skates.js`, a subclass of `Skateboards.js` with its own profile id, object type and poses; the nearest of bike, board and skates wins an interact press); Jonas starts on his. Poses (`scenes/SkatesArt.js`, per character palette as `player-<id>-skates` plus `-pushA`, `-pushB`, `-crouch`, `-grab`): alternating push-offs while accelerating, a glide pose at speed (`push.glideFrac`), crouch for the hop. The jump intent is a small hop (`trick.ollie`), and skates grind rails, bounce off ramps and score Style through the same `TrickSystem` (several roller services, `trick` block without a manual; Jonas has no trick multiplier). The `hold` intent is the level of the interact button.

**Bus grab**: `entities/GrabTargets.js` drives pooled kinematic road vehicles along the looping routes of `data/routes.json` (`{ id, map, kind, count, speed, points }`; kind `bus` for now, trams and the traffic of epic 12 reuse the class: kinds, sizes and grab zones are in `data/grab.json`). Two buses (145 px/s, a bike at 150 still overtakes them) loop the town's main road: eastbound in the south lane, westbound in the north lane, with half-circle turns at the ends. A bus is a SENSOR body from the bodies factory, so it harms nobody (a comic hit by moving buses belongs to the traffic epic) and is drawn with a yellow handle at the rear; vehicles expose `x, y, heading, vx, vy, speed`. A rider on skates (`grab: true` in the profile) near a bus sees the yellow rear zone; holding F inside it (press F early, it is not a dismount within `armRange` of a bus) hangs on: the rider is towed at the bus speed (a clear boost over the skates' 112), on a rope, in a low grab pose with sparks and a risk bar over its head; steering sideways swings it up to `swingMax` px. The failure model is pure (`vehicles/grabLogic.js`): a hazard per second grows with speed, bumpiness (the surface `rattle`: cobble is nasty), swing and time, and the risk bar is the chance that it has already failed; `busGrabBonus` (Jonas 0.5, Mehmet 0.1) lowers the hazard and extends the 8 s limit. Ends: `jump` (ollie off, Style bonus), `release` (button let go), `tired`, `lost` (rope snagged on a wall), `fail` (a comic tumble with spins and a short slowdown, no harm, no loss), plus `vehicle`, `caught`, `map`. Events: `grab:start { player, target, kind, x, y }`, `grab:end { player, target, reason, time, risk, x, y }` and `trick:grab { player, phase, reason, time, score }`, which scores a `grab` trick (`data/tricks.json`: points plus per second, `grab.jumpBonus` for the ollie off; the combo timer stands still while hanging on). A new grab needs the button let go first. Co-op: each player has their own grab state. The ticket inspector hooks come with epics 7 and 8, the full traffic with epic 12. Decisions: the buses are faster than the skates (so a tow is a boost); a grab is cut off when the rope is stretched past `snapSlack` (a wall in the way).

## The town

**Skatepark** (story 5.4, AD-28, CAP-15): the bully-turf plaza east of the park is a real concrete skatepark (tile x 46..67, y 34..45, fenced, gates in the north and west fence). Trick objects (`ramp`, `rail`, `stairs`, `bench`, new `manual-pad`, `bank-spot`) form the obstacles: a quarter-pipe pair, a funbox with a ramp up each side, a 3-step stair set with a handrail, a long flat rail, a kinked rail, three ledge benches, a manual pad, and a bowl suggested by ramps with the bank spot in its pit. Two `trick-line` objects (a `points` polyline plus its `steps` ids) are the designed routes: the main line is west gate -> ramp -> ollie onto the long rail -> ollie off -> stair jump -> U-turn -> manual along the pad -> ollie out -> slowly through the bank spot; its arrows are painted in `?debug`/`?bench` sessions only, and a `sign` object (the "Lines" hint, toast `park.sign.lines`) explains the order. The entrance outside the north gate has two skateboards and a pair of skates (the usual item objects), a `bike-rack` (see Vehicle ownership below) and `lamp` posts stand around the plaza. Entering or leaving the `skatepark` turf shows a HUD toast (`toast` / `toastLeave` i18n keys on the `turf` object, shown by `entities/Zones.js`); the turf itself, bully spawns and chase rules are unchanged. Art is procedural and drawn once per map load by `entities/Park.js` + `scenes/ParkArt.js` (concrete slabs with joints, stains and scuffs, funbox, bowl, manual pad, bank ring, gate posts, graffiti decals SKATE / LOS and shapes, lamp, rack and sign sprites; the ramps, rails, benches and stairs are drawn by `vehicles/trickArt.js` with coping lips and shading), layout and decals in `data/park.json`; stains and scuffs are skipped on Low. `node scripts/check-skatepark.mjs` checks the design (catalog, no object in a wall or on another, every trick type has an obstacle, line order and connectivity, bike access through the gates, entrance items, art data); the smoke scenario `skatepark` skates the whole main line. `SCHULWEG_BENCH.smoke(['skatepark'])` runs a single smoke scenario.

`data/maps/town.json` is a 96x64 tile town (16 px tiles): a main road with a bike lane, a park with a canal, pond and bridge, an old town with cobbled alleys, a skatepark, and the school with a fenced yard. Walking from home to the school takes about 30 seconds by either of two routes: along the main road, or through the park and over the canal bridge into the old town. The yellow arrow around the player points to the school and shows the distance in meters (`metersPerTile` in the map); arriving emits `goal:reached` and shows a short message. Legend chars map to surface ids; surfaces with `"solid": true` in `data/surfaces.json` (walls, water, trees, fences, hedges, dumpsters, phone booths) become static bodies. Map objects: `spawn`, `goal`, `bike`, `hiding` (hedge, dumpster, phone-booth sensor zones), `turf` (skatepark, schoolyard-back sensor zones), `bully-spawn`, and `prop` markers (cone, can, crate, ball), `flag` and `ambient` (steam, chimney) spots. Each player entering or leaving zones emits `hide:enter|leave` and `turf:enter|leave` (`{ id, kind, player }`) on `ctx.events`; `goal:reached` is `{ id, player }`. Player events carry the player index: `player:surface` `{ player, id }`, `player:stamina` `{ player, value }`, `player:vehicle` `{ player, id }`, `tool:*` and `ammo:pickup` `{ player, ... }`. With `?debug`, hiding zones are outlined green, turf zones red and the goal yellow.

**Maps and interiors (AD-28).** Every map, interiors included, is one file in `data/maps/` (listed in `data/maps/index.json`; the town is map id `town`). `ctx.world.load(mapId, entryId)` is the only way to switch maps: it unloads everything map-specific (ground texture, wall bodies, zones, doors, props, pickups, bikes, flags, ambient emitters, pedestrians, bullies, puddles), builds the new map, moves every player to the entry (an `entry` or `spawn` object) with a quick fade-in and updates camera bounds, objective arrow, path grid and surfaces. Pools and players persist; a ridden bike travels along. It emits `world:leave` `{ map }` and `world:enter` `{ map, entry }`. A `door` object (`to`, `entry`, `label`, optional `auto`) emits `world:enter-request` when a player stands in it and presses interact (or, with `auto: true`, just touches it); the switch happens at the start of the next frame. Maps may set `"indoor": true` (no rain, no daylight tint). Systems that depend on the map register with `ctx.world.register(system)` and implement `loadMap()` / `unloadMap()`. `data/object-types.json` lists every object type with fields, required flags and wall rules (door, entry, rail, ramp, stairs, bench, dojo, shop, bakery, pfand-machine, bike-rack, tram-stop, sign, mission-trigger, grab-target, home-spot, school-spot are defined for later stories). `test-room` and the town's `door-test` are flagged `debug` and exist only with `?debug` or `?bench`: stand on the doormat next to the house at the start and press F.

`node scripts/check-map.mjs` validates the maps: grid shape, legend, objects (none inside walls), and that the school is reachable by two different, bike-friendly routes, even when the middle of either one is blocked.

**Vehicle ownership, racks, theft and rescue** (story 5.5, AD-16, AD-22, AD-23, AD-25, CAP-16): vehicles belong to the family: `state.shared.ownedVehicles` (an id list, walking is always owned, saved with the slot). Every character's start vehicle is unlocked when the run starts (`vehicles.unlock { id, reason }`, reasons `start`, `bought`, `race`, `garage`); `player.setVehicle(id)` (and with it every mount of a lying item) is refused for a vehicle that is not owned, with the toast `vehicle.locked` ("Das gehört dir noch nicht - im Laden oder bei Rennen freischalten!") and the interact press used up; lying vehicles that are not owned yet wear a red padlock (`entities/Parking.js`) and become usable as soon as the type is unlocked. Unlock paths: (a) the action `shop.buyVehicle { id }` takes the price from `data/shop.json` (cents: skateboard 4500, skates 5500, bike 6000) and checks money and ownership atomically (the shop screens come in epic 10); (b) the event `race:won { vehicle }` (races come in epic 9); (c) the `garage` map object (`vehicle`, `hiddenFlag`), a garage door beside home (tile 18,50; interact once: skateboard, sparkle, discovery toast, flag `garageFound`, the door stays open; the home interior comes in epic 8). `vehicles/Ownership.js` (`ctx.ownership`) turns every unlock into `vehicle:unlocked { id, reason }` plus a toast.
**Racks and theft**: a bike you get off within `rackRadius` (44 px) of a `bike-rack` object (skatepark, home tile 11,51, school) is chained: `parkState` 'locked', closed lock and chain, safe from borrowing, and mounting it with interact takes the lock off. Anywhere else it stays 'unlocked' (open lock as the hint). Once every player has been further than 400 px from an unlocked bike for 20 s (`data/theft.json`), every second a bully may borrow it (30% per check, out of view) when there is a motive: Aerger >= 1, an active bully, or a bully spawn within 450 px. A thief appears at the nearest off-view bully spawn, walks to the bike (a player coming within 70 px scares it off: `bike:theft-foiled`), rides it along an A* path to the nearest `bike-hideout` (town: skatepark back, bridge underpass) and leaves it there. On pickup it emits `bike:stolen { player, bikeId, hideoutId }`, shows the blue phone toast "Dein Fahrrad wurde geborgt!", emits `mission:trigger { id: 'stolen-bike' }` for the epic 9 quest runner and sets the fallback flag `shared.flags.stolenBike = { hideout, x, y, bikeId, map }`, which the objective arrow follows ("Fahrrad: 120 m") until the quest runner takes over; the flag is saved, and the bike is put back at its hideout after a reload or map switch. Rescue: any player who walks up to the bike and presses interact mounts it, which clears the flag and emits `bike:recovered`; the first player near the hideout raises Aerger once (the guard, via `bully:bump`). The thief is a plain sprite (no body, no Aerger of its own); bikes from the map that nobody has dropped are not tracked. Rules are pure in `vehicles/theftLogic.js`, the loop is `entities/BikeTheft.js`, art in `scenes/VehicleArt.js`. `node scripts/check-vehicles.mjs` checks the actions, the Ownership service, saves, the rules, the data and A* paths from every bully spawn to every hideout; the smoke scenario `vehicles` walks every unlock path and the whole theft loop with accelerated timers (`ctx`-side test hooks: `gs.theft.cfg`, `gs.theft.rng`). New object types in `data/object-types.json`: `bike-hideout`, `garage`.

## Menu, language and quality

The main menu has Play (opens the save slot screen), a language toggle (Deutsch / English) and a quality selector (Low / Medium / High); use the mouse, touch, or arrow keys + Enter. Esc (or the pause button, or Start on a gamepad) opens the pause overlay in the game with Resume, the same two toggles, and Back to menu; it shows the active slot and the mode with the characters. A new game asks Solo or Co-op first (see Co-op).

Save slot screen: three slots with a summary line (player(s), level, day, money). Per slot: New game (asks before overwriting an occupied slot), Continue, Delete (asks too); Esc or Back goes one screen up. Starting or continuing a slot binds it as the active slot, so autosave on `phase:ended` writes to it. An unreadable save is copied to `.bak` when the screen opens and shown as empty with a note. New game continues to the character select (below); day phase/playtime in the summary come with later stories.

- Language: switches instantly (all HUD and menu text re-resolves on the `lang:changed` event) and is saved in `localStorage` key `schulweg.lang`. All visible text lives in `i18n/de.json` and `i18n/en.json` and is read with `ctx.t('key')`.
- Quality: tiers are in `data/quality.json` (particle and prop caps, bullies, NPCs, rain density, pool sizes, shadows; Medium is the AD-14 budget). The choice is saved in `schulweg.quality`; desktop starts on High, phones (coarse pointer or small screen) on Medium. `?q=low|medium|high` overrides it for one load. Switching between Medium and High applies live; switching to or from Low changes the render resolution (480x270 vs 960x540), which is fixed when the page loads, so the game shows "Neustart nötig ..." / "Restart needed ..." and reloads itself with the new tier saved. Changing it emits `quality:changed`; pooled effects (skid marks, smoke, bell rings) change their active cap without allocating.
- `?debug` also shows the current tier, render size, texture scale and zoom, and live/cap counts of every pool under the HUD.
- Smooth zoom (story 1.13): world textures are bilinear filtered, the zoom is a damped spring (`data/camera.json`: `smooth`, `maxRate`, `deadband`) and the camera only snaps to whole pixels at an integer zoom. `node scripts/zoom-sweep.mjs --tier medium` (serve the game first) sweeps the zoom range and reports smoothness numbers (see `docs/PERFORMANCE.md`).
- Render resolution: world units, physics and tuning data are the same on every tier. On Medium and High the canvas is 960x540, the world camera runs at base zoom 2 (the speed zoom 0.6-1.0 in `data/camera.json` multiplies it), all procedural textures are drawn on a 2x grid (`scenes/HiResArt.js`, shown at scale 0.5, with tile variants, facades with windows, outlined sprites) and the UI keeps its 480x270 layout through a zoomed UI camera with text rendered at 2x. Low keeps the 1x art from `BootScene` and zoom 1.
- `node scripts/check-i18n.mjs` checks that both language files have identical keys and no empty values, and that every `t('...')` key used in the source exists.

## Living world

- **Wind** (`physics/Wind.js`, tuned in `data/weather.json`): `ctx.wind.vector` is the single wind state, a gust pattern that changes slowly. Each consumer applies it itself: leaves, rain and steam through emitter gravity, light props (`windAccel` in `data/props.json`, scaled by mass) through a small force, and the flags near the school and in the park, which droop in a breeze and stream and ripple in a gust. With `?debug` a wind arrow shows at the lower left and the wind vector and weather state in the debug text.
- **Weather** (`physics/Weather.js`): press **T** to toggle clear / rain (the `weather` intent; no touch button yet). Rain fades in a darker tint, drops fall across the view slanted by the wind with small splash rings, and dry roads turn into puddles (via the surfaces override API, only used by weather); they dry out again when it stops. Emits `weather:changed`.
- **Particles** (`particles/ParticleHub.js`, `data/particles.json`): a few shared emitters created once, fired with `ctx.particles.emit(name, x, y, opts)`: `dust` (sprinting, bike drifting), `splash` + `ripple` (moving through puddles), `leaves` (kicked up on grass, plus an ambient swirl), `rain`, `steam` (bakery, manhole and a chimney) and `debris`. The effect under you comes from the surface's `particle` name in `data/surfaces.json`. Each emitter gets a share of the tier's `maxParticles`; burst sizes follow `particleMul` and rain follows `rainDensity`, re-read on `quality:changed`. Fish occasionally ripple the pond.
- **Props** (`entities/Prop.js`, `data/props.json`): cones, cans, crates and balls from the map markers are Matter bodies in the `PROP` category. Walk or ride into them to push them; cones tip over on a hard hit, cans roll, the ball bounces far, a crate breaks into debris when hit fast (about sprint speed or more). Strong hits emit `prop:hit` with `{ prop, speed }`. Props away from the camera sleep and are not drawn; at most the tier's `maxProps` are awake.

## Chase (Ärger, bullies)

- **Ärger level 0-2** (`ai/ChaseDirector.js`, rules in `ai/ChaseLevel.js`, tuning in `data/chase.json`): the director is the only writer of the level and the only spawner of bullies. Entering bully turf (skatepark, back of the schoolyard) raises it to 1 and spawns a foot bully at the nearest `bully-spawn` point outside the camera view; staying in turf (`turfSecondsPerLevel`) or a bump (`bully:bump`, also a near-miss with a bully that is not chasing) raises it to 2, which adds a bike bully and a second foot bully (never more than the tier's `maxBullies`). Emits `chase:level` `{ level, reason }` and `chase:seen`. `chaseEnabled: false` in `data/chase.json` keeps the level at 0 (hook for a parent setting).
- **Service for later stories** (`ctx.chase`): `level`, `seen` (some bully sees the player), `cool(seconds)` (level falls to 0 after that long and the bullies give up), `reset()` (level 0, bullies removed at once), `playerCaught()` (used by the caught flow). Contact with a bully emits `bully:caught-contact` `{ bully, player }` and freezes it in `CAUGHT`. The caught flow is below.
- **Two players** (`ai/chaseLogic.js`, `coop` in `data/chase.json`, AD-18): one shared Ärger level that rises from the turf or bumps of either player. A bully chases the nearest visible player (distance over `bullyTargetWeight`) and keeps that target until another visible player scores below `switchRatio` (0.6) of its score, so it does not flip-flop; spawns are picked outside the camera view that holds both players, and `level.coopExtraByLevel` adds at most one bully (never past the tier's `maxBullies`). Cooling is judged per player (one `Escape` each): the level only drops when EVERY player in play is safe, hidden for `hideSeconds` or far and unseen for `farSeconds`. A hider whose partner is still seen or near a bully keeps the chase on. The HUD hide bar shows the slowest player.
- **Bully states** (`ai/BullyFSM.js`): `IDLE` (short beat after spawn), `CHASE`, `SEARCH` (walk to the last seen spot, look around), `DISTRACTED` (a `prop:hit` within `distractRadius` makes a bully that is not watching the player walk to the hit point), `STUMBLE` (story 6.3, see Karate defense), `GIVE_UP` (walks to the farthest spawn point and vanishes out of view; when the last bully is gone the level drops to 0), `CAUGHT`. Bullies use the movement profiles `bully-foot` (a bit slower than sprinting) and `bully-bike` in `data/vehicles.json`, and are pooled (`entities/Bully.js`, pool `bullies`). Their bodies do not collide with the player; contact is a proximity check.
- **Seeing** (`ai/Perception.js`): view distance and field of view from `data/chase.json`, grid raycast against solid tiles. Standing almost still (below `hideSpeed`) inside a hiding spot makes you invisible, and a hidden player is not caught or bumped.
- **Pathfinding** (`ai/Pathfinding.js`): grid A* over the map (walls blocked, surface speed and wall proximity as cost), requests queued with a shared budget of 2 per frame, per-bully cached path re-requested about every 0.5 s or when the target tile changes, straight-line steering when the way is clear. A full-map search takes about 0.25 ms in node.
- **HUD and debug**: top right an Ärger meter (two bars) and "Entdeckt!" / "Spotted!" while seen; angry steam puffs over chasing bullies (`anger` emitter). `?debug` shows each bully's state, path, line-of-sight ray and bump radius plus the level in the debug text.
- **Escaping** (`ai/Escape.js`, `escape` in `data/chase.json`): stand still in a hiding spot, unseen and with no bully within `stumbleRadius`, for `hideSeconds` and the level drops to 0 (bullies walk off and return to the pool). Being seen, moving, leaving the spot or a bully stumbling close resets the timer and the level stays. Staying farther than `farDistance` from every bully and out of sight for `farSeconds` also cools the level down. While hidden the player sprite turns translucent and green, leaves rustle, the HUD shows "Versteckt!" / "Hidden!" and, during a chase, a bar under the Ärger meter fills until the level drops. Still only the director writes the level.
- **Caught** (`entities/Caught.js`, `ui/CaughtFrame.js`, `caught` in `data/chase.json`): `bully:caught-contact` freezes the world (`ctx.frozen`; UIScene keeps running; with two players only while both are caught, see below), spends `lossCents` (100) from `ctx.state.shared.money` (starts at 500 cents, shown top left as "€ 5,00"), resets the chase and shows a comic frame (halftone panel, locker with the player inside, the bully with the lunchbox, a random one of three speech-bubble lines per language). After 2.5 s, or Space/F (A/Y on a gamepad, jump button on touch) once 0.8 s have passed, the player is dismounted (the bike stays where it was), put back at home with a dust puff, and the chase can start again at the next turf entry. Caught is per player: the caught player is pinned (`Player.pinned`: stands still, no input, tools drop their charge, no bike or ammo or door use) and out of play (`Player.alive = false`: bullies and the crowd ignore it), loses one fine from the shared wallet, and respawns beside the spawn point on its own timer or press. The other player keeps playing; the world freezes only while everyone is caught, and the first respawn unfreezes it. In co-op the catching bully gives up, other bullies carry on, and the level resets once no bully is chasing any more. The comic frame is scaled to `caught.coopScale` (0.5) and shown on the caught player's HUD half (P1 left, P2 right), so the other player keeps a clear view. Emits `player:caught` `{ player, lost, money }` (cents) and `player:respawn` `{ player, x, y }`.
- Reaching the school (`goal:reached`) shows the arrival banner for a few seconds; the game keeps running (prototype, no school scene).
- `node scripts/check-chase.mjs` checks pathfinding on the real map (home to school, walls, request budget, timing), the level thresholds, the hide / distance escape rules and the two-player rules (target hysteresis, escape across players, spawn counts, off-view spawns).

## Slingshot

Hold the left mouse button (touch: hold the tool button and drag from it to aim; gamepad: RT, right stick aims) to charge for about 0.8 s, release to shoot. Aim at the cursor; without a pointer the shot goes the way you last walked. While charging, a rubber band and power ring show at the player, a dotted line shows the flight, and a wind arrow with strength shows at the bottom of the screen; the dots bend with the wind exactly like the pebble (`flightPoint` in `tools/Slingshot.js`). **Q / E** cycle tools (`ToolBelt`; the tools and their order are `belt` in `data/tool.json`: slingshot, throwing stick, stick). The HUD shows the tool and its ammo.

A hit pushes the prop (`knock` in `data/props.json`), crates take 3 hits, a spark puff shows, and `prop:hit` is emitted with the hit position (trash cans use `hitRadius` 260, cans 100, others the bully default), so bullies that are not watching you go to look (`DISTRACTED`).
- Targets: 3 tin cans on the skatepark fence (map props with `"perch": true`, static until hit) and a trash can nearby.
- Ammo: start with 5, magazine cap 12 (`data/tool.json`). Pebbles, chestnuts and acorns lie around (`ammo` map objects); walk over one to pick it up, it reappears after 40 s. The aim-dot count scales with the quality tier (`aimDots`).

## The stick: bushes, crates, doorbells, pinata, balloons

Story 6.2 (CAP-17, AD-24). Press **E** / **Q** until the HUD says "Stock" / "Stick" (third on the belt), then click (touch: tap the tool button; gamepad RT). A swing is a short arc of 22 px in the aim direction (110 degrees, 0.35 s cooldown, a swoosh is drawn); `data/tool.json` `stick` has the numbers. What it can hit is decided by a query of **objects only** (`tools/swingLogic.js`: props, bushes, doorbells and the pinata; no list of people or animals is ever passed in and the query skips any body that is not PROP or STATIC; `scripts/check-stick.mjs` and `scripts/check-collisions.mjs` test this). At most 3 targets per swing, nearest first.

- **Crates and boxes** (props): `data/props.json` `crate` (hp 3, two swings) and the weaker cardboard `box` (hp 1) smash with wood splinters or paper scraps and emit `prop:broken`; they may hide coins (`loot`). **Cones, cans and balls** fly off (`Props.knock` with the stick's `damage` and `knockMul`).
- **Bushes** (map object `bush`, 11 in the town): whack one 3 times (`hp`) and it drops one thing from its table (`data/stick-world.json` `bush.tables`: coins, slingshot ammo, a sticker, the lost homework, or nothing) as a collectible you walk over (`entities/LootDrops.js`). The table is rolled with a seeded generator; a bush gives out once per game day (flag `bush-<id>-day`). The lost homework sets `flags.lostHomeworkFound` (and emits `homework:found`) for the later mission, stickers emit `sticker:found` (epic 10 stub).
- **Doorbells** (map object `doorbell`, 3 houses): swing at one or press interact next to it: `doorbell:ring` { player, houseId }, a "Ding-Dong!" bubble, then the door opens, `neighbor:alert` { houseId, player } is emitted and a placeholder neighbor (a pooled sprite without a body, `data/neighbors.json`) shouts and follows you at walking speed for 6 s, then gives up laughing. If he reaches you nothing happens but an "Erwischt!" bubble. The real angry neighbor chaser comes in epic 7 (story 7.4) and takes over `neighbor:alert`.
- **Pinata** (map object `pinata`, a party frame with bunting, table and cake near the meadow at the left of the town): 4 whacks burst it into confetti, candies, coins and a sticker (`pinata:burst` { player }, once per game day, flag `pinata-<id>-day`). There is no energy meter yet, so candies are worth a few cents.
- **Kirmes balloons** (map objects `balloon` and `fair-stall`, same meadow): slingshot shots pop them (static PROP sensor bodies, so projectiles that only see PROP and STATIC still reach them), `balloon:popped` { player, color }, confetti, back after 45 s. They bob and lean with the wind.

New object types are in `data/object-types.json` and validated by `scripts/check-map.mjs`; the pure logic (zone geometry, object-only query, loot, ding-dong-run timers, pinata hp, balloon respawn) is in `tools/swingLogic.js` and `entities/stickWorldLogic.js`, checked by `node scripts/check-stick.mjs`; the smoke scenario is `scripts/smoke/stick.js`.

## Throwing stick and dog fetch

Story 6.1 (CAP-17, AD-24). Press **E** (or **Q**) until the HUD says "Wurfstock" / "Throwing stick"; it shows `bereit` (in your hand), `fliegt!` (in the air), `liegt da` (on the ground) or `der Hund bringt ihn` (a dog has it). Hold the tool button to charge for about 1 s (the power ring and the dotted path show the throw, bent by the wind), release to throw. Power sets the distance (60 to 220 px in calm air, `data/tool.json` `throwingStick`); the character perk `stickThrowRange` multiplies it (Mehmet 1.4x), Zielen scatters the aim a little (`spreadDeg`).

- **One stick**: it flies a long arc (spinning sprite, shadow on the ground, own mass and drag for the wind, the same `flightPoint` maths as the slingshot, AD-7) and then lies on the ground with no timeout. Only its owner picks it up, by walking over it, so there is nothing to throw until it is back. A map switch puts it back in your hand. Events: `tool:throw { player, power }`, `stick:landed { player, x, y, dist }`, `stick:pickup { player }`, `tool:ammo`.
- **Objects only** (AD-3): the stick is a `PROJECTILE` sensor body, so people, bullies and animals never touch it and it never pushes anything. High in its arc it flies over walls and props lying on the ground; low (just after the throw and as it comes down) it knocks balls and cones and stops at walls, and anything perched up high (a frisbee in a tree, a can on a fence) is hit at any height. A stick that ends up in a wall, a tree or water rests on the last free point of its path (`tools/stickLogic.js`).
- **Prop kinds** `frisbee` and `kite-stuck` (`data/props.json`) are perched in trees (`"perch": true` on a map `prop` marker: the town has two frisbees and one kite) and fall to the ground when hit. Perched cans sit on fences, perched frisbees and kites on tree tiles (checked by `scripts/check-map.mjs`).
- **Noise**: a thrown stick is loud, its `prop:hit` radius is `hitRadiusMul` (1.5) times the prop's own `hitRadius` (trash cans, cans), so bullies far away get DISTRACTED (the existing `ChaseDirector` handler).
- **Dog fetch** (`ai/DogFetch.js`, glue in `entities/NeighborDogs.js`, data in `data/dogs.json`): free-roaming dogs are `ANIMAL` bodies with the states CALM, CHASE and FETCH. A dog in CHASE with a landed, unclaimed stick within `fetch.range` runs to it, carries it (drawn in its mouth), drops it near the thrower, celebrates with a heart burst and returns to CALM. If the owner picks the stick up first, or a fetch takes too long, it drops out of it. Dogs are never hurt or pushed by anything. Events `dog:fetch-start` / `dog:fetch-done { player, dog }`. `ctx.dogs.spawn(x, y, state = 'CHASE')` creates a dog (`SCHULWEG_GAME.spawnDog(x, y, state)` with `?debug`); until epic 7 builds the chasing neighbor dog, a chasing dog only trots after the nearest player.
- `node scripts/check-tools.mjs` checks range, perk, wind, contacts, settling, pickup rules and the fetch FSM; `scripts/check-collisions.mjs` also asserts that the stick never touches people or animals; the smoke scenario `throwingStick` plays it all in the running game.
## Karate defense (block, dodge, Kiai)

Story 6.3 (CAP-19, AD-24). Non-violent: the kid blocks, rolls away or shouts; bullies only **stumble** back comically, nobody is hurt, pedestrians and animals just gasp ("Oha!"), props are untouched. `defense/DefenseController.js` (`ctx.defense.forPlayer(i)`, also `player.defense`) runs one slot per kid with the states `IDLE`, `BLOCK`, `DODGE`, `KIAI`, `RECOVER`; the rules are Phaser-free in `defense/defenseCore.js`, the visuals in `defense/DefenseFx.js` and `scenes/DefenseArt.js`, the numbers in `data/karate.json`.

- **Controls**: hold **R** (P2 `;`, pad X, shield button) to block; press it while walking to roll in that direction (dodge); press **V** (P2 `'`, pad right-stick click, burst button) for the Kiai. In co-op the touch buttons drive P1 only. The first trouble of a save shows the tip toast (`flags.defenseHint`). Gamepad X no longer fires the tool (RT does).
- **Mut** (courage) is the 0..1 pool every move spends (bottom corner HUD bar `ui/hud/DefenseModule.js`, with a thin Kiai cooldown strip that turns yellow when the shout is ready): a block costs per absorbed contact and a little per second held, a roll and a Kiai a fixed amount; it refills after a short delay. Walking is slow while blocking and stops during roll and shout.
- **Belts**: `belts` in `data/karate.json` is the stat table (`kiaiRadius`, `kiaiCooldown`, `blockWindow`, `dodgeDistance`, `dodgeCooldown`, `stumbleDuration`, `aergerReduction`); the kid's row comes from `state.players[i].karate.belt` (only `white` exists; stories 6.4/6.5 add rows).
- **Block**: while the guard is up (at most `blockWindow` seconds, then it drops and recovery is slower) a bully reaching the kid does not catch it: it bounces back with a "Hmpf!" (`defense:blocked`). A contact in the first 150 ms is a **parry** (free, +2 XP, flash, `defense:parry`). **Dodge**: invulnerable for the roll plus a short grace, then a cooldown (a press during it just blocks). Contacts are answered through `ctx.defense.contact(player, bully)`, which the chase director asks before it catches.
- **Kiai**: every bully within `kiaiRadius` that is after somebody (IDLE, CHASE, SEARCH, DISTRACTED) stumbles; if one did, Ärger drops by `aergerReduction` through `ctx.chase.defend(reason, amount)` (the director stays the only level writer; only while the level is within `level.defendMaxLevel` in `data/chase.json`, now 2, so epic 7's levels 3-5 work by raising that number; reaching 0 ends the chase like any clear, and level 0 stays 0). Either kid's Kiai reaches bullies chasing either kid. Events: `defense:kiai { player, radius, affected }`, `bully:stumble { bully, x, y, reason }`, `defense:state`, `defense:dodge`, `defense:blocked`, `defense:parry`, `defense:guard-down`.
- **Stumble** (`STUMBLE` in `ai/BullyFSM.js`): a scripted step backwards along the line away from the kid over `stumble.step` (0.5 s, eased) with a sprite wobble and dizzy stars, applied as plain position changes (wall-checked) and never as a Matter force; then the bully resumes (a level that fell to 0 sends it off instead). A stumbling bully cannot catch or bump. Only bully objects are ever passed to the stumble; the Kiai's reach function returns pedestrians and animals separately as gasp-only.
- Procedural poses per character palette (`player-<id>-block|kiai|dodge`), guard arc, "KIAI!" burst and shockwave rings. Decision: the speech bubbles (`entities/SpeechBubbles.js`) now show at 6 world px (they were drawn at a quarter of their intended size).
- `node scripts/check-defense.mjs` checks the state machine, costs and cooldowns, contact answers, Kiai reach (never pedestrians or animals), the level gating, the stumble integration, the STUMBLE state and that no stumble code applies a force; the smoke scenario `defense` (`scripts/smoke/defense.js`) plays Kiai, parry, block, dodge, the gasp, cooldowns, the HUD bar and two kids.

## Pedestrians and crowd

The town is full of people so it looks lively wherever you are (`ai/CrowdDirector.js`, `entities/Npc.js`, tuning in `data/npcs.json`, art in `scenes/NpcArt.js`).

- **Population**: up to `maxNPCs` of the quality tier (Low 6, Medium 12, High 20) from the pool `npcs`, re-applied live on a tier switch. They appear on `npc-spawn` map markers (about 125, with district and role) in a ring just outside the camera view and are removed again once they are far outside it, so the crowd follows you through the districts; the density per district (`districts` in `data/npcs.json`) steers where they gather (plaza and park busiest, skatepark quietest). The level is filled on start.
- **Walking**: `npc-node` markers form a graph of sidewalk, park path, alley and schoolyard waypoints; walkers go node to node along straight corridors (checked by `scripts/check-map.mjs`), sometimes stopping to chat. No pathfinding is used, bullies ignore pedestrians.
- **Roles**: walkers (adults, kids, slower grandparents with canes), standers (bus stop, plaza, school gate), a grandparent on a bench, someone feeding the ducks, dog walkers (the dog is a pooled `ANIMAL` body on a leash) and two kids kicking a ball back and forth in the park. 12 outfits, three frames each, drawn procedurally at the render scale.
- **Reactions**: ringing the bell (`bike:bell`) within 85 px, or riding at them quickly from the front, makes them hop, step aside perpendicular to your heading and shout a kid-safe line (`npc.react.N`, six per language, at most 3 speech bubbles at once); very fast and very close they dash away. Event `npc:react` `{ x, y, state }`; `bike:bell` carries `{ x, y, player }`.
- **Physics**: pedestrians are `NPC` bodies (feather-light, so you push them aside instead of getting stuck), they collide with walls, props and the player, never with bullies, each other or tools; dogs only with walls and props. The slingshot passes through all of them (AD-3).
- `?debug` shows the crowd state counts, a label per pedestrian and the pools `npcs`, `dogs`, `bubbles`. `node scripts/check-crowd.mjs` checks the spawn rules, caps and reaction geometry.

## Learning engine

`ctx.learning` (`learning/LearningEngine.js`, Phaser-free logic in `learning/engineCore.js`, tuning in `data/learning.json`) is the only code that picks questions and writes learning stats (AD-19). Questions are generic topic files `data/learning/<grade>/<topic>.json` (`{topic, grade, bothLangs, items[{id, topic, type, difficulty 1-5, q:{de,en}, answers, explain:{de,en}, hints, tags}]}`) listed in `data/learning/index.json`. Klasse 3 content: `grade3/mathe.json` (230 items: Einmaleins, Division, Addition/Subtraktion bis 1000, Zahlenreihen, Länge, Gewicht, Geld, Uhrzeit, Geometrie, Sachaufgaben) and `grade3/deutsch.json` (225 items: Artikel der/die/das, Rechtschreibung, Wortarten, Mehrzahl, Wortfamilien, Satzzeichen, Gegenteile; 23 typed items may carry `caseSensitive` (nouns need their capital) and `strictUmlaut` (the item is about ä/ö/ü/ß, so "ae"/"ss" do not count)), `grade3/englisch.json` (261 items, `bothLangs`: Vokabeln, Gruß- und Alltagssätze, Satzbausteine, Hinweis-Rätsel/Matching, `signs` for the sign-scanning feature), `grade3/sachkunde.json` (233 items: `geo`, `karte`, `verkehr`, `zeit`, `natur`, `koerper`, `wasser`, `strom`; DE-first, proper nouns kept, `q.en` translates the task) and `grade3/science.json` (161 items: `wasser`, `magnet`, `strom`, `circuit`, `pflanzen`, `tiere`, `ernaehrung`, `material`, `licht`, `schall`). Arithmetic items may carry an `expr` (e.g. `"7*8"`) that `scripts/check-learning-content.mjs` evaluates against the stated answer; that script also checks schema, bilingual text, UI lengths and the item counts per difficulty. Choice answers are plain strings (the same in both languages), typed items list the accepted forms.

Learning content schema beyond `choice` and `typed` (all validated by `scripts/check-learning-content.mjs`, served untouched by `next()`, judged by `isCorrect`; the UIs come with the minigames of epic 4):

- `fact: {de, en}` (optional, at least 25% of Sachkunde and Science items): a fun fact for stickers.
- `type: "match"`: `pairs: [{left, right}]` (3-4 pairs, texts are strings or `{de,en}`, right sides unique; the UI shuffles them). Response for `isCorrect`: one entry per left side in order, the index of the chosen right side (or its text); correct only when every pair is right.
- `type: "sort"`: `categories: [{id, label}]` (2-3) and `sortItems: [{text, category}]` (4-6). Response: one category id per sort item in order (array, or object keyed by index); correct only when every assignment is right.
- `circuit` items (tag `circuit`, Science) are ordinary `choice` items plus `circuit: {cells, goal: "bulb-on", ask: "lit"|"fix", lit, fix?}` for the Science minigame (`minigames/circuitCore.js` solves them). `cells` is ONE series loop in list order, each `{id, kind: battery|bulb|wire|gap|switch|bridge, state?: open|closed, item?: {de,en}, conducts?: boolean}` (a `bridge` is a gap closed by an object, e.g. a paper clip, which conducts or not). The bulb is on when the loop has a battery and a bulb, every switch is closed, there is no `gap` and every bridge conducts; `lit` states that result and the checker recomputes it. `ask: "lit"` asks whether it lights (the correct answer starts with "Ja" exactly when `lit`); `ask: "fix"` has a dark bulb and `fix` lists the cell ids that must be changed (switch to closed, gap or non-conducting bridge to wire) to light it.
- `bothLangs` topics (only `englisch`): every item's `q` and `explain` carry a German and an English text that differ and are shown together; typed answers are accepted case-insensitively.
- `sign` (items tagged `signs` in Englisch): the English text as printed on a shop sign, in capitals, for the sign scanner.

- `next(topic, { player, context })` returns the item plus `meta` (`difficulty`, `target`, `timeFactor`, `hintsAllowed`, `expectedMs`, `due`, `bothLangs`). `answer(question, ok, ms, { player, hintsUsed })` records it (state action `learning.record`, emits `learning:answered`) and returns UI feedback data; `due(player, { topic, maxCount })` lists items due for repetition; `localize(question, lang)`, `isCorrect(question, response)` and `feedback(question, ok)` are the presentation helpers. Reaction lines come from `data/learning/reactions.json` (i18n keys `learning.react.*`); a wrong answer never costs anything, it shows the explanation and a gentle line. English topics set `bothLangs` and always show both languages.
- Adaptivity: the level (1-5, fractional) follows the accuracy of the last 10 answers. Inside 75-85% nothing changes (hysteresis), below that it drops, above it rises, twice as hard beyond 70% / 90%. Struggling kids get 1.5x time and every hint, strong ones 0.85x time and no hints; fast correct answers ramp up quicker. The parent modifier `state.shared.flags.parentDifficulty` (default 1, clamped 0.5-1.5) scales the target difficulty and time.
- Repetition: a wrong item is parked for 3 answered questions, then due; each correct answer moves it up (intervals 3, 8, 20), after the last box it counts as learned. Due items are mixed in at the context's `dueRate`, forced when overdue by 2, and `context: 'bully'` asks them first.
- Stats live in `state.players[i].learning[topic]` (the existing `learning` object, so no save version bump: missing fields are filled when read) and are saved with the slot. `SCHULWEG_GAME.learning` is available with `?debug`. `node scripts/check-learning.mjs` runs weak, average and strong simulated learners.

## Grading and Kopfnoten

`ctx.grades` (`grading/Grades.js`, Phaser-free logic in `grading/gradeCore.js`, tuning in `data/grading.json`) is the only code that maps a score to a German grade (AD-20). `grades.grade(player, subject, { score, effort, difficulty, lessonId })` turns a minigame result into a grade 1-6, writes it with the `grades.record` action and emits `grades:recorded`; `reportCard(player, lang)` bundles what the Zeugnis (epic 8) shows.

- Thresholds (Klasse 3): 92% = 1, 81% = 2, 67% = 3, 50% = 4, 30% = 5. Gentle on purpose: a gain of 10 points over the previous result in the subject (`trend`) or effort of 80% (share of questions tried, hints count) lifts the grade by one step, at most one step in total, never worse than the base grade and never above 1. Each difficulty step above 3 adds 2 points to the score. Below 30% it is still a 5; a 6 only happens with a score under 5% and effort under 25% (basically nothing done).
- Ledger: `state.players[i].grades = { entries, bySubject }` (save version 3, migration from v2; entries are capped at `gradesMaxEntries`, the per-subject tallies are not). `average(player)` gives per-subject averages and the overall mean of the subject averages (one decimal), `countOf(player, grade)`, `trend(subject)`.
- Promotion: `evaluatePromotion(grades, kopfnoten)` takes the Zeugnis grades (the rounded subject average, x.5 goes to the worse grade). Promoted when the one-decimal average is at most 4.0 and at most two grades are 5 or worse (a 6 counts as one bad grade). It returns `{ promoted, average, fives, conduct, reasons, comebackBonus }`: `reasons` are encouraging i18n keys, `comebackBonus` (xp, money cents, perk) is set only for a repeated year. Kopfnoten are reported but never decide.
- Kopfnoten (`data/kopfnoten.json`): verhalten, mitarbeit, ordnung, hilfsbereitschaft, values 1-4 (4 is best, stored fractionally, start 3, clamped). The event table moves them through the `kopfnoten.add` action (for example `traffic:red-light` with adults nearby lowers Verhalten, `homework:forgotten` lowers Ordnung, `lesson:done` with effort raises Mitarbeit, `npc:helped` raises Hilfsbereitschaft); events nobody emits yet simply never fire. The data file is merged into the state config at boot.
- Texts: `data/teacher-comments.json` (39 warm, funny comments, chosen by subject strengths and weaknesses, improvement, conduct and the overall band; the pick is deterministic per ledger) and `data/parent-reactions.json` (12 promoted and 12 repeat lines) only hold i18n keys (`teacher.comment.*`, `parent.*`), so the content lint covers them. `teacherComment(grades, kopfnoten, lang)` returns the text.

## Minigames

`ctx.minigames` (`minigames/Minigames.js`, Phaser-free logic in `minigames/minigameCore.js`, registry and tuning in `data/minigames.json`) is the one way to run a minigame (AD-20). `start(id, { players: [0], difficulty, context, lessonId, topic })` returns a Promise that resolves with `{ id, subject, quit, difficulty, score 0-1, effort 0-1, correct, total, hintsUsed, xp, moneyCents, grade 1-6, ms, stats, perPlayer[] }` after the player left the result screen and the world is back. With `?debug`, `SCHULWEG_GAME.startMinigame('quiz-demo', { players: [0, 1] })` does the same from the console (`await` it, or `.then(console.log)`).

- Registry entry: `{ id, subject, scene: "MG_<id>", durationSeconds (30-90), rewards { xp, moneyCents }, topics, maxPlayers (1 or 2), difficultyRange, expectedQuestions, debug? }`. A new minigame adds an entry there, its scene class to `minigames/index.js`, and the title key `minigame.<id>.title`. `debug` entries (the two demos) are only listed in `?debug` sessions. `learning: false` (Musik, Kunst, Sport) means no learning-engine questions: `topics` is empty and the scene counts its results with `countResult(slot, ok, ms, topic)` (a note hit, a right cell) instead of `record()`.
- A minigame is a Phaser scene extending `minigames/Minigame.js`. The base owns the 480x270 layout space (crisp text like UIScene), the visible 3-2-1 countdown, the shared timer bar, the pause button, one playing area per player (the whole screen for one player, two halves side by side for two) and one answer cursor and tally per player. The subclass implements `buildGame(slots)`, `onStart()`, `updateGame(dtMs)` and optionally `navigate(slot, nav)`, answers through `record(slot, question, ok, ms, hints)` (feeds `ctx.learning.answer` and the tally) and ends with `finish()`. Input comes only from `ctx.input.intents[player]`: arrows/WASD or the stick to move the focus, Space/F/Enter/pad A to confirm, number keys 1-4 (P1: the top row, P2: the numpad) to pick an answer directly, plus click or tap on a button. `QuizDemo.js` is the template for the real minigames.
- **Mathe** (`minigames/MatheGame.js`, id `mathe`, 70 s, 1-2 players, pure logic in `minigames/matheCore.js`, tuning in the registry entry's `options`): two modes in one run. *Kopfrechen-Sprint* asks `ctx.learning.next('mathe')` items on a chalkboard `QuestionPanel` (answer buttons; typed items on the numeric `ui/Keypad.js`: arrows + confirm, 1-4 type that digit, tap, with a hint key). *Fallende Blöcke* (`ui/BlockField.js`) lets the 2-4 answer blocks of an item (typed items get generated near-miss distractors) fall in lanes towards the floor: left/right moves the catcher, confirm takes the block above it, 1-4 takes that lane, down asks for a hint, a tap takes a lane. The fall time starts at `fall.baseMs`, gets shorter per engine difficulty level and is scaled by the item's `timeFactor` (a struggling child gets slower blocks, more hints), within `minMs`/`maxMs`. `options.mix` picks the modes per run: `alternate` (two halves, `first` = `sprint`, `blocks` or `random`, `switchAt` = share of the round), `random` (one mode per run) or a fixed mode. Both modes feed every answer to `ctx.learning.answer` (ms, hints) and count the same way. No lives: a wrong answer or a block that lands uncaught shows the right answer, the explanation and a funny line, then the round goes on. A streak from `combo.from` shows a combo label and bigger sparkles. Two players play side by side with separate streams; the leader gets a short gentle cheer (cosmetic, both earn the full reward).
- Flow: `start` pushes a `minigame` screen (freezes the world through the counted screen stack, so pause and the result screen nest on it), ducks the HUD (`ctx.duckHud`, touch controls stand down) and starts the scene (registered in `main.js`, stopped again afterwards) above the game. Esc or the on-screen pause button opens the normal pause screen, which gains an "End minigame" row; time stands still while it is open. Ending early counts as low effort (effort capped, no rewards, no result screen, a friendly toast). Otherwise `finish()` builds the result: per player score (correct against at least `expectedQuestions`), effort (share tried), the grade from `ctx.grades.preview` (the only score-to-grade mapper; the framework does not record grades, the day flow does through `ctx.grades.grade`), then `xp.add` per player, `wallet.earn` once and the event `minigame:done { id, result, players }`. Rewards scale from `minRewardShare` up to the full amount with the score.
- **Deutsch** (`minigames/DeutschGame.js`, id `deutsch`, 70 s, 1-2 players, pure logic in `minigames/deutschCore.js`, tuning in the registry entry's `options`): two modes in one run, mixed by `options.mix` like Mathe. *Artikel-Sortierer* (`ui/BeltField.js`): the noun of an Artikel item (`ctx.learning.next('deutsch', { filter: 'artikel' })`) rides a conveyor belt in a wooden crate towards three bins, der (blue, square), die (red, circle), das (green, triangle; colour, shape and word mark each bin); left/right moves the selector, confirm sorts, 1-3 sorts at once, down asks for a hint, a tap on a bin sorts. The belt time starts at `belt.baseMs`, gets shorter per engine difficulty level and is scaled by `timeFactor` within `minMs`/`maxMs`; a noun that reaches the end is a gentle miss. *Rechtschreib-Detektiv*: the spelling sub-tags (`spellTags`) in the chalkboard `QuestionPanel` (choice buttons) or, for typed items, on a letter pad (`ui/Keypad.js` with `LetterPadModel`: a-z, ä ö ü ß, Shift for the next capital, back, hint, OK; arrows + confirm or tap). With one player the physical keyboard types too (letters incl. umlauts, Backspace, Enter). A typed answer is matched by `matchTyped`: spaces trimmed, case ignored unless the item is `caseSensitive`, "ae"/"oe"/"ue"/"ss" accepted for umlauts and ß unless `strictUmlaut`; the engine's `isCorrect` confirms the matched accepted answer. No lives: wrong answers show the right answer, the explanation and a funny line; two players play side by side, the leader gets a gentle cheer. `next()` takes an optional `filter` (a tag, an array of tags or a predicate) for this. Art is drawn with Phaser graphics (bins shaded with `HiResArt`'s `lighten`/`darken`), no textures.
- **Englisch** (`minigames/EnglischGame.js` on `DuelMinigame.js`, id `englisch`, 70 s, 1-2 players, pure logic in `minigames/englischCore.js`): two modes in one run, mixed by `options.mix`; every text is shown in both languages. *Vokabel-Memory* (`ui/CardGrid.js`): face-down cards, English words (blue, tag EN) and their German meanings (yellow, tag DE); arrows + confirm or a tap turn two cards, a pair stays up, a miss turns back after `memory.peekMs`. A board is dealt from engine items (`dealBoard`): one `match` item (its 3-4 pairs, one answer when the board is done) or four vocabulary / sign `choice` items (each pair is its own answer when matched; the pair comes from "Was heißt \"X\" auf Englisch/Deutsch?" or from the item's `sign`). Mistakes only count when both flipped cards had been seen before (finding cards is never punished); a pair with more than `memory.maxFaults` such mistakes is answered wrong (then the explanation shows). *Schilder-Check* (`ui/SignPlate.js`): a bolted shop-sign plate (OPEN, PUSH, BAKERY ... coloured red/green/blue/dark by meaning) with the meaning picked in the `QuestionPanel`; typed `signs` items use the letter pad of Deutsch. Two players get their own boards and streams; the leader is cheered like in Mathe/Deutsch.
- **Erdkunde** (`minigames/ErdkundeGame.js` on `DuelMinigame.js`, id `erdkunde`, subject `erdkunde`, 70 s, 1-2 players, pure logic in `minigames/erdkundeCore.js`): *Wo liegt ...?* shows the question above a big map and the player taps the state or river (arrows jump from target to target with `geoCore.stepTarget`, confirm picks); *Hauptstadt-Match* highlights the state on a mini map beside the answer buttons and shows the capital dot with its name afterwards. Items come from `ctx.learning.next('sachkunde', { filter })` and are tied to the map by `data/learning/grade3/geo-map.json` (`itemId -> targetId`; the mode follows from the right answer being the target's name or its capital); unmapped geo/karte choice items appear now and then (`options.fallbackShare`) as plain choice buttons. - **Science** (`minigames/ScienceGame.js` on `DuelMinigame.js`, id `science`, subject `science`, 70 s, 1-2 players): two modes mixed per run by `options.mix` plus short Quick-Quiz questions. *Sortier-Labor* (`ui/SortLab.js`): the items of a `sort` task (or the left sides of a `match` task, whose right sides become the bins) arrive one by one as lab cards; drag the card into a test-tube bin, tap a bin, or use the cursor (left/right + confirm, up = hint) or the number keys; after the last card the engine's `isCorrect` judges the whole set, wrong cards are listed with their right bin. *Stromkreis-Tüftler* (`ui/CircuitBoard.js`, solver in the Phaser-free `minigames/circuitCore.js`): the `circuit.cells` loop of a dark-bulb item is drawn procedurally, the player picks the part that stops the current (tap, cursor + confirm or keys 1-5): a needed repair (switch closes, gap or insulator becomes a wire) is applied and with the last one the bulb lights with a glow, spark particles and flowing current dots; picking a part that works already ends the puzzle with a gentle line why the current still cannot flow, the explanation and the solution. Puzzles are the `ask: "fix"` items (declared `fix`) plus the dark `ask: "lit"` items whose repairs the solver finds (`puzzleFix`); lit circuits and missing-part circuits play as Quick-Quiz questions. *Quick-Quiz*: every other choice item in the `QuestionPanel` after `options.quizEvery` puzzles; a wrong answer shows the right one, the explanation, the item's `fact` (`panel.showFact`, `localize().fact`) and a funny line. - **Musik** (`minigames/MusikGame.js` on `DuelMinigame.js`, id `musik`, subject `musik`, 60 s, 1-2 players, `learning: false` = no learning-engine questions, the score is the share of notes hit): a four-lane rhythm game on a small concert stage (`ui/RhythmStage.js`: curtains, spotlights, lanes, hit line, arrow pads). One chiptune song per run from `data/songs.json` (4 original songs with BPM and an 8-bar loop chart per tier easy/medium/hard, `charts[tier][bar]` = 8 steps of `.` or a lane digit, singles only; the loop repeats mirrored to fill the round); each player gets the tier that fits `difficulty + 0.15 * (level - 1)` (`tierRule`), so two kids can play different charts of the same song. Play: P1 `A S W D` (lanes left to right) or `1`-`4`, P2 arrows or numpad `1`-`4` (with one player WASD, arrows and `1`-`4` all work), the gamepad d-pad, or tap the lane / pad. Windows are gentle (perfect +-70 ms, good +-140 ms, scaled up for easy tiers); a miss only breaks the combo, a press with no note near is ignored. The beat is the round clock: pausing stops the song, and the game is fully playable without sound (a metronome ring pulses on every beat). The Jonas perk `musicArtBonus` (`data/characters.json`) widens the windows and multiplies the points by the same share and shows a "Talent-Bonus" label. Audio hooks for the audio epic: `music:note { player, lane, grade, pitch (MIDI: song.root + scale[lane]), song, tier, combo }` per judged note, `music:beat { beat, bpm, song }` per beat, `sfx:play { name: 'musik.perfect'|'musik.good'|'musik.miss'|'musik.combo'|'kunst.*', ... }`. **Reusable core** `minigames/rhythmCore.js` (Phaser-free, also for the instrument-practice chore): `songFor`, `tierFor(difficulty, level, rule)`, `buildSchedule(song, tier, { durationMs, leadInMs, tailMs, lanes, stepsPerBar })` -> `{ n, t[], lane[] }` (deterministic), `windowsFor(cfg, tier, bonus)`, `judgeOffset(dt, windows)`, `new NoteTrack(schedule, lanes, windows)` with `press(lane, now)` / `sweep(now)` / `range(now, ahead, behind)` / `state[]` / `counts`, `new Scorer(scoring, bonus)` (`hit(grade)`, `miss()`, combo multiplier), `beatPhase`, `noteY`, `lanesFromNav`, `accuracyOf`. Drive it with one clock in ms.
- **Kunst** (`minigames/KunstGame.js` on `DuelMinigame.js`, id `kunst`, subject `kunst`, 60 s, 1-2 players, `learning: false`, pure logic in `minigames/kunstCore.js`, view `ui/PixelEasel.js`): "Pixel-Muster merken". A pixel pattern is shown on an easel for a few seconds (bar; Enter skips ahead), then hidden, and the player paints it again on an empty canvas with a colour palette (the pattern's colours plus a decoy from level 3). Levels in the registry entry (`options.levels`): 4x4 / 2 colours up to 7x7 / 5 colours with a memorize time from 6.5 s down to 4.5 s; the level starts at the difficulty and adapts per pattern (a perfect copy makes the next one harder, below 50 % easier, i.e. struggling kids get bigger time and smaller grids). Jonas' `musicArtBonus` extends the memorize time by that share. Patterns are seeded (`mulberry32`): mirrored noise (left-right or four-way), stripes, checker and the hand-authored icons of `data/pixel-patterns.json` (heart, star, house, smiley, tree, mushroom ... per grid size, recoloured now and then). Painting: arrows move, Enter paints (hold it while moving for a stroke), `1`-`4` pick a colour, arrow down from the last row enters the palette row (colours, then "Fertig"), or paint with mouse / finger (click, drag; swatches and Fertig are tappable). Every cell is one answer in the tally (a half-right copy earns half; unpainted cells are wrong), a perfect copy celebrates with sparkles, the result view shows pattern and copy side by side with a dot on wrong cells and a friendly line; if the timer ends mid-painting the copy is judged as it is.
- **Sport** (`minigames/SportGame.js` on `DuelMinigame.js`, id `sport`, subject `sport`, 60 s, 1-2 players, `learning: false`, pure logic in `minigames/sportCore.js`, views `ui/SportTrack.js` + `ui/sportArt.js`): "Hindernislauf" in the school gym, seen from above. Decision: a self-contained scene with its own lanes (no extra map file): every player runs their own lane with the **real `MovementController`** and the `foot` profile of `data/vehicles.json`, on a kinematic body inside `sportCore.Runner`, so the world stays frozen and no Matter world is needed. The character's **Tempo** sets the speed and **Ausdauer** the sprint stamina (`computeMods` of `data/characters.json`, read from `ctx.players[i].attrs`). Controls: move with WASD / arrows (P2: arrows), Shift sprints (the stamina bar runs dry, then you are slower), Space (confirm) jumps. Course (one per difficulty, `options.levels`): start sprint lane, cone slalom (cones on the centre line, weave around them), middle run, hurdles across the whole lane (jump in time), a balance beam on mats (slip off and the mats slow you), a final sprint to the finish; five stations with flags. Knocking a cone or hurdle or wobbling off the beam never blocks: it adds a few seconds (0.5 / 0.8 / 0.7 s, `options.knock`) and a short stumble. Two players run side by side in two lanes. Score = points of 100: progress 30 %, time 40 % (between the slow reference, a neutral kid walking, and the par, a clean sprint with Tempo/Ausdauer 8 - both simulated by `sportCore`'s bot on the same movement code), cleanliness 20 % (fewer than `faultCap` knocks), finish bonus 10 %; an unfinished run earns what it covered and its effort is the covered share. Faster two-player runner is cheered gently. Hooks: `sfx:play { name: 'sport.jump'|'sport.knock'|'sport.clear'|'sport.checkpoint'|'sport.finish'|'sport.tired', player }`.
- **The map** (`data/maps-geo/germany.json`, geometry in `minigames/geoCore.js`, drawing in `minigames/ui/GermanyMap.js`): hand-authored low-poly Germany in [lon, lat]; the 13 area states are rings of shared border point names (neighbours share their borders exactly, the country outline is derived as the union), Berlin, Hamburg and Bremen are small blobs on top, plus capitals, six rivers (Rhein, Main, Weser, Elbe, Donau, Oder) as polylines and the Nordsee and Ostsee. `GermanyMap` is reusable (the tram map quiz 9.4): `layout(rect)`, `setTargets('states'|'rivers'|'seas')`, `setHighlight(id, style)`, `setHover(id)`, `pick(x, y)`, `drawCapital(id)`, `drawRiver(id)`, `anchors()`, `onTap`. `geoCore.js` is Phaser-free (`pointInPolygon`, `nearest`, `stepTarget`, `pickAt`, `makeLayout`, `outlineOf`).
- Result screen (`ui/screens/MinigameResultScreen.js`, screen id `minigameResult`): 0-3 procedural stars, the German grade with a kind headline, a funny line per result band (`minigame.react.*`, DE and EN), correct count, XP and money, per-player lines for two players, and "Continue" by click, tap, confirm key or pad.
- `QuestionPanel` renders a learning item in the current language (`bothLangs` topics show both), numbered answer buttons for `choice` items, a hint button (as many as the engine allows) and kind feedback: the funny reaction, the right answer lit green, and after a mistake the correct answer plus the explanation. Typed, match and sort items need their own interaction in their minigames. `Timer` and `ScorePop` (floating `+1` and a sparkle emitter from the particle registry, scaled by the quality tier) are shared too.

## Day clock

`ctx.day` (`services/DayClock.js`, pure time math in `services/dayTime.js`, all tuning in `data/day.json`) owns game time 06:30 to 22:00 and the phase machine morning, commute, school (from the 08:00 deadline), afternoon, evening, then the next day. One game minute takes `secondsPerGameMinute` real seconds (1.6, so a day is about 25 minutes). The time is `ctx.state.shared.clock` (`{ day, minute, phase }`), changed only by the `clock.set` action and restored with a loaded slot.

- Phases change only through `ctx.day.advance(reason)` (`'time'` when the clock runs out). Events: `clock:tick` (per game minute), `phase:ended` / `phase:started` (`{ phase, reason, day }`). When `phase:ended` fires the state already holds the next phase, so the autosave stores where to continue.
- Each phase has a season (autumn morning and commute, winter school, spring afternoon, summer evening) and weather hints (rain chance per time window, rolled once per day). `Weather` follows them; **T** is only a debug override until the schedule changes. A soft time-of-day tint (dawn warm, day neutral, evening orange, bedtime dark) sits in the weather overlay.
- Without a save slot (for example a quick start from the debug console) the clock is in freeplay: it shows the `freeplay` time from the data and never ends a phase. `ctx.frozen` stops the clock unless `runWhileFrozen` is set.
- The HUD shows a season icon, `HH:MM` and the phase at the top centre.
